# 통계적 위험 보정과 결과 해석

## 평가 단위

보정·Test의 표본은 독립적으로 생성한 원본 episode 한 개입니다.
학습 분기 row, checkpoint, 같은 seed의 반복을 독립 보정 표본으로 계산하지 않습니다.
수집에 5,760개 분기가 있어도 보정 표본이 5,760개인 것은 아닙니다.

## 실제 구현한 보정

1. train/dev에서 모형·개입·후보 정책 목록을 결정합니다.
2. 새로운 calibration episode 전체를 각 후보로 실행합니다.
3. 기준 성공 episode 수 n+와 후보 때문에 실패한 수 k를 셉니다.
4. `p = BinomialCDF(k; n+, epsilon)`을 계산합니다.
5. 사전에 고정한 모든 비-Continue 후보에 Holm step-down을 적용하여 FWER delta를 통제합니다.
6. 통과한 후보 중 **개발 자료의 최종 성공률**이 가장 높은 후보를 각 family에서 선택합니다.
7. 통과 후보가 없으면 무개입으로 돌아갑니다.

기존 LTT의 위험 검정을 통한 유한 후보 선택 원리를 적용한 것이며 새 이론을 주장하지 않습니다.[S10]
후보 간 결과가 상관되어도 Holm의 적용 자체는 후보별 독립성을 요구하지 않습니다.
반면 calibration episode의 독립성, 같은 평가 분포, 후보의 사전 고정 등은 필요합니다.

## 보장 범위

전제 조건 아래에서, calibration 자료의 무작위성에 대해 선택된 후보의 모집단 조건부 악화율이
목표를 넘는 잘못된 선택 확률을 delta로 제한하는 해석입니다.
각 상태의 안전, Test에서 관측된 비율이 매번 epsilon 미만일 것, 미관측 OOD 분포,
실물 환경의 손상 방지, 저지연 실행을 보장하는 것이 아닙니다.
하나의 모델·한 번의 보정과 Test만으로 보장 위반 빈도를 실증했다고 쓰지 않습니다.

## 주의할 숫자

k=0이고 후보 하나인 경우, epsilon=.05/delta=.05에서 n+가 59개는 필요합니다.
이는 0사건 상황의 최소 예시이며 일반적인 검정력 분석이나 전체 episode 수가 아닙니다.
여러 후보와 양의 악화 사건이 있으면 더 많은 자료가 필요합니다.

```bash
python -m hci sample-size --epsilon .05 --delta .05 --candidates 19
```

n+=0이면 조건부 악화 추정은 undefined입니다. 이를 0으로 넣어 통과시키지 않습니다.
Harm을 관측하지 못했다는 것과 Harm이 없다는 것은 다릅니다.

## 목적함수

기준 성공률 b, 조건부 구조율 rho, 조건부 악화율 H라면
`success = b*(1-H) + (1-b)*rho`입니다.
구조율만 최대화하지 않습니다. 본 코드는 인증된 후보 중 개발 성공률로 선택합니다.

## 오경보와 악화

무개입이면 기준 궤적과 같은 실행이라는 전제에서 `H <= P(trigger | Y0=1)`입니다.
따라서 오경보 제어가 악화 제어를 전혀 하지 못한다고 주장하면 잘못입니다.
직접 결과 보정의 가설은 보수성을 줄여 유익한 개입을 허용하는지에 관한 것입니다.

## 금지

- 보정 후보 목록을 calibration 성능을 본 뒤 계속 추가하기.
- Test에서 잘 나온 epsilon을 주 결과로 선택하기.
- 같은 seed의 여러 분기를 독립 episode처럼 이항 검정에 넣기.
- 재실행 불일치율을 Harm에서 단순히 빼고 같은 이항 보장을 주장하기.
- pointwise 95% 신뢰구간을 모든 후보에 대한 동시 95% 보장으로 읽기.
- 모든 작업을 섞어 평균 위험만 만족시킨 뒤 작업별 위험도 만족한다고 쓰기.

여러 epsilon, 작업, 정책에서 동시 보장을 주장하려면 해당 다중성까지 오류 예산을 배분합니다.
기본 코드는 한 작업·한 기본 정책·주 epsilon 하나의 후보군에 대한 보정입니다.

## 결과 보고

최종 성공률, 성공률 차이, conditional Harm/Rescue, 원래 성공한 실행에서의 개입률,
개입률, 완료 step, 추론 시간, seed 단위 신뢰구간을 보고합니다.
현재 `summarize`의 bootstrap은 원본 episode를 재표집합니다.
학습 seed 변동성은 별도로 보고해야 하며 이 interval이 그것까지 포함하는 것은 아닙니다.
