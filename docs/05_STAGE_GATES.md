# 단계별 작업과 산출물

기간보다 실제 산출물을 기준으로 진행합니다. 문헌조사로 돌아가는 것을 기본 단계로 두지 않습니다.

| 단계 | 수행 | 필수 산출물 | 다음 단계 조건 |
|---|---|---|---|
| 0 환경 | 고정 버전 설치, CPU 검사, CUDA/Vulkan/RGB smoke | pip freeze, doctor, smoke 로그 | 실제 RGB와 상태 검사 통과 |
| 1 기본 정책 | 시연 변환, 짧은 학습, 정식 학습, EMA export | config, demo hash, checkpoint, 성공/실패 영상 | 정상 행동·성공 판정 확인; 미숙련이면 학습 보완 |
| 2 분기 | 정책 포함 audit, 2개 원본의 분기 수집 | audit JSON, 3개 개입 영상, 데이터 4분할 | 상태·정책 replay 일치, 비슷한 상태의 각 행동 확인 |

| 5 보정/동결 | 새 calibration 평가, LTT/Holm, 해시 동결 | selection, freeze manifest, Test 계획 | 보정 전제·불변 파일·예산 검토 |

## Stage 0~2에서 먼저 해야 할 구체 작업

실제 정책이 물체를 움직이는 영상을 저장합니다. 학습 손실만 보고 정책이 정상이라고 판단하지 않습니다.
Refresh 전후 남은 chunk 길이와 첫 행동 변화를 기록합니다. 자연 경계의 noop를 효과적인 개입으로 세지 않습니다.
Retreat의 TCP 이동·그리퍼 명령·소모 step을 측정합니다. 목표 물체를 몰래 옮기지 않습니다.
복원 전/후 관절·물체·관측·행동·성공 결과를 비교합니다. 현재 제공되는 기본 audit에 부족한 상태가 있으면
개발 범위에서 audit coverage를 늘리고 산출물에 명시합니다.

## 본 실험 전에 추가할 것 — 현재 코드에 완료되었다고 주장하지 않을 항목

1. **시각 자료**: 주요 성공/실패/Rescue/Harm 사례의 동일 시점 영상. 기본 runner는 저장 공간을 위해 영상 저장을 생략했습니다.
2. **rate-matched controls**: 개발 자료에서 빈도 맞춘 무작위/타이머 후보. 현재 고정 확률 후보를 바로 rate-matched라고 부르지 않습니다.
3. **H2 대조**: 같은 선택기/동일 후보 공간에서 FPR 보정과 Harm 보정 비교.
4. **정책 seed**: 최소 3개를 초기 본 실험 제안으로 고려하되 실제 분산/비용에 따라 사전 선언합니다. 3이 보편적 출판 기준은 아닙니다.
5. **관측 ablation**: 현재 vs 짧은 이력 vs privileged diagnostic. 기본 코드에는 동결 DP 이력 특징만 구현했습니다.
6. **실패 메커니즘**: 시간 초과와 물리적 상호작용 악화를 사례별로 분석. timeout label만으로 물리적 원인을 단정하지 않습니다.
7. **coupling/latency 민감도**: 난수 대응 규칙과 계산 지연 모델이 결론을 바꾸는지 확인.
8. **확장 분포**: 초기 배치 외의 마찰·가림·지연은 별도 교란 모듈로 추가하고 원본 in-distribution 보장과 구분.

## 진행 판단

개입별 효과가 다르고 관측으로 일부 구분된다면 선택기를 개발합니다.
특정 간단한 행동이 항상 최선이면 복잡한 모형을 강제하지 않습니다.
Q+같은 보정으로 충분하면 새 Joint 예측기 우월성 주장을 내리지 않습니다.
복원·난수·시간 예산 문제가 원인이면 모델을 키우지 말고 프로토콜부터 고칩니다.
