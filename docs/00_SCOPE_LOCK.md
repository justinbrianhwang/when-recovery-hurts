# 연구 범위와 결정 기록

버전: v0.3 / 기준일: 2026-11-12

## 연구 질문

고정된 로봇 조작 정책에서 관측 기반 선택기가 Continue, Refresh, Retreat–Retry 중 무엇을 언제 실행할지 결정할 때,
기준 실행의 성공을 실패로 바꾸는 비율을 제한하며 최종 작업 성공률을 높일 수 있는가?

기준 결과 Y0, 선택기 g 적용 결과 Yg는 0/1이며 목표는

`maximize P(Yg=1), subject to H(g)=P(Yg=0 | Y0=1) <= epsilon`.

여기서 H는 인명·충돌·기계 손상 위험이 아니라 **작업 성공 결과의 악화**입니다.
시뮬레이터와 미리 선언한 확률 대응 규칙에 상대적인 값입니다.

## 지금 고정할 사항

| 항목 | 결정 |
|---|---|
| 대상 | Panda 계열 단일 로봇팔, 시뮬레이션만 |
| 초기 환경 | ManiSkill3 v3.0.1 pinned commit |
| 로봇 ID | `panda_wristcam` — 두 본 작업에 공통으로 지원되는 Panda 구성 |
| 기본 정책 | 공식 RGB Diffusion Policy 구현을 학습한 뒤 동결 |
| 행동 | Continue / Refresh / Retreat–Retry |
| 개입 횟수 | 한 episode에서 비-Continue 최대 1회 |
| 온라인 입력 | RGB, qpos, qvel, TCP pose, 관측 이력, 이전 행동, 현재 제어 step |
| 기본 물리 | CPU 단일 환경, GPU 렌더링과 신경망 |
| 첫 작업 | StackCube; PickCube는 설치 확인 |
| 확장 작업 | PegInsertionSide |
| 주 악화 허용값 | epsilon=.05, 보정 오류 예산 delta=.05 |
| 학습할 것 | 개입 선택기; 기본 로봇 정책이나 복구 원시 동작은 개입 데이터 수집 전 동결 |

CPU 물리를 택한 것은 초기 재현성 검사와 공식 시연 경로 일치를 위한 실험 운영 결정입니다.
ManiSkill GPU 물리의 성능이나 적합성에 대한 부정적 결론이 아닙니다. 병렬화는 별도 검증 후 추가합니다.

## 개발 중 정하고 보정 전에 동결할 것

정책 학습량과 체크포인트, horizon, 관측 encoder, 결정 시점 간격, retreat 거리·속도·횟수,
데이터 수집량, 후보 임계값, 모형 구조, 허용 가능한 복원 오차입니다.
기본 YAML 숫자는 시작값이지 검증된 최적 설정이 아닙니다.
모든 변경은 `templates/AMENDMENT.md`에 기록합니다.

## 이번 패키지에서 하지 않는 것

새 VLA 학습, LLM 복구 생성, TDA 추가, 인간 원격 개입, 실물 로봇 전이,
반복 개입, 강화학습 전체 재설계, 테스트 결과를 본 뒤 임계값 수정은 제외합니다.

## 가설

H1: 개입 효과는 상태·작업 단계·개입 종류에 따라 다르며, 고정된 위험 순서만으로 설명하기 어렵다.
H2: 같은 선택기에서 결과 악화율을 직접 보정하는 것이 오경보율만 제한하는 것보다 유용한 개입을 더 허용할 수 있다.
H3: 같은 관측·분기 데이터·보정 절차에서 도움/악화 분리 예측이 Q 추정기보다 추가 의사결정 가치를 갖는다.

H1~H3는 가설입니다. Refresh가 항상 안전하거나 Retreat가 항상 위험하다고 전제하지 않습니다.
현재 코드에는 H3의 주 비교 구조가 구현되어 있습니다. H2의 오경보 보정 비교는 본 실험 확장 항목입니다.

## 기여 주장 범위

4분할 결과 정의, 분기 실행, Q와 성공 확률의 연결, 기존 LTT 이론 자체는 새 기여라고 주장하지 않습니다.
파일럿에서는 비교군의 실제 차이와 왜 차이가 생기는지를 확인합니다.
차이가 없을 때 분석 결과로 전환하는 것은 가능하지만, 무의미한 실험도 자동으로 논문이 된다고 주장하지 않습니다.
