# 데이터와 모델 계약

## 1. Split

| split | 기본 seed | 용도 |
|---|---|---|
| audit | 100~104 | 복원·제어 흐름 검증 |
| train | 10000~10119 | 분기 라벨과 예측기 학습 |
| dev | 20000~20099 | 설계·후보 선택·개입 동작 조정 |
| calibration | 30000~30399 | 동결 후보의 위험 검정 |
| test | 90000~90399 | 최종 보고용, 잠금 |

숫자는 사전 선언한 초기 규모입니다. 시연 학습 데이터는 별도의 공식 demonstration 데이터입니다.
같은 원본 episode의 checkpoint와 반복을 train/dev 사이에 나누지 않습니다.
서로 다른 정책 학습 seed를 비교할 때 같은 평가 초기 seed를 대응시켜 사용할 수 있지만,
위험 보정과 통계 분석에서는 정책별 결과를 구분하고 공통 보장을 주장할 때 다중성을 처리합니다.

## 2. 학습 데이터 파일

`runs/branches_*/dataset.json`: config/policy hash, 사용 seed, 분기 수, 수행 시간, 완료 여부.
`episodes/<seed>.npz`: `x`, `action`, `y0`, `y`, `step`, `repeat`, `episode`.
`episodes/<seed>.json`: 수집된 체크포인트 수와 원본 성공 결과.

`x`는 동결된 DP 영상 encoder의 현재 관측 이력 표현 + 관절 이력 + 직전 행동 + 시간/남은 큐 비율입니다.
기본 encoder 자체를 재학습하지 않습니다. 부가적인 객체 정답 위치나 task success는 포함하지 않습니다.
물리 상태 스냅샷은 초기 수집에서 메모리 안에서만 사용하며 데이터 파일에 전체 장면을 직렬화하지 않습니다.

`action`: 0 Continue, 1 Refresh, 2 Retreat–Retry.
각 대응 결과는 `class=2*y0+y`입니다: 0 둘 다 실패, 1 Rescue, 2 Harm, 3 둘 다 성공.
같은 반복의 Continue 기준을 이용하며, 다른 반복의 기준 결과를 섞지 않습니다.

## 3. 예측기

Q: 3개 개입 선택지의 최종 성공 확률을 sigmoid 출력으로 추정합니다.
각 row에서는 실제로 실행한 action 출력에만 binary cross entropy를 적용합니다.
이는 지도식 Monte Carlo 가치 추정이며 Bellman backup을 하는 Q-learning 구현이 아닙니다.

Joint: 비-Continue 2종별 4가지 대응 결과의 확률을 softmax로 추정합니다.
이익 점수는 `P(rescue)-P(harm)`이며 선택 후보에 따라 Harm 가중 페널티를 추가합니다.
소프트맥스 출력이 통계적으로 보정되었다고 가정하지 않습니다. 별도 전체 episode 보정이 필요합니다.

두 모형은 같은 동결 관측 특징, 같은 분기 데이터, 2층 128폭 MLP를 사용합니다.
출력 head 차이로 정확히 같은 파라미터 수는 아니며 `training.json`에 각각 기록합니다.
제안 방법에만 추가 상태 정보나 더 많은 rollout을 제공하지 않습니다.

## 4. 비교군

`never`: 기준 정책.
`timer`: 미리 정한 시간 이후 가능한 첫 검사 시점에 지정 개입 1회.
`random`: 검사 시점마다 고정 확률로 개입하되 최대 1회.
`risk_q`: 기준 실패 위험에 임계값을 적용하고, 종류 선택은 같은 Q 추정기로 수행하는 강한 비교군.
`q`: 최대 예상 성공률 향상에 따라 종류와 실행 여부 선택.
`joint`: Rescue/Harm을 별도로 학습한 점수로 종류와 실행 여부 선택.

모든 학습된 선택기는 동일한 두 복구 선택지와 동일 episode 보정을 사용할 수 있습니다.
타이머·무작위 비교군도 각 행동 후보를 포함합니다.
기본 무작위 후보는 아직 **빈도 매칭을 완료한 비교군이 아닙니다**. 개발 자료에서 개입 빈도를 맞춘
추가 후보를 선언한 다음 보정 전에 registry를 동결해야 논문에서 rate-matched라고 쓸 수 있습니다.

## 5. 모델을 바꾸기 전 진단

학습 손실, 각 outcome class 수, 작업별 기본 성공률, action별 성공/악화 분포를 확인합니다.
모두 실패하거나 모두 성공하는 정책은 초기 파이프라인 확인에는 쓸 수 있지만 주 비교에 충분한지는 별도 문제입니다.
성공률을 일부러 낮추기 위해 평가 분포를 몰래 바꾸지 않습니다.
고전적 점수와 Q가 충분하다면 그 결과를 받아들이고 모형 크기를 계속 키우지 않습니다.

## 6. 데이터 보존

중단된 수집은 `completed=false`이며 학습기는 이를 거부합니다.
부분 결과를 재사용하려면 포함 seed와 실패 이유를 명시한 새 manifest를 만드는 별도 복구 절차가 필요합니다.
조용히 실패 seed를 빼거나 성공한 파일만 모아 complete로 바꾸지 않습니다.
